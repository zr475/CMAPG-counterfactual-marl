## 一、项目背景

- **竞赛**：第21届全国大学生智能汽车竞赛 — 人工智能视觉组
- **比赛模式**：虚实结合、硬件在环（Hardware-in-Loop）
- **核心任务**：OpenART 摄像头拍摄车载手机屏幕上的游戏画面，实时识别+决策，通过 UART 控制车模完成游戏任务
- **场地**：约 3.2m × 2.4m，5cm 黄色布基胶带边界
- **定位**：全局快门彩色摄像头（架设高度 ≥1.8m）识别车顶标识牌 + 场地四角 AprilTag（编号 15-18）
- **当前拟定任务**：推箱子；练习/备赛系统含飞机大战

---

## 二、系统架构

```
全局摄像头(定位车模位姿) → 裁判系统(运行游戏逻辑+渲染+WiFi投屏)
                                    ↓
                          手机屏幕(车载，显示游戏画面)
                                    ↓
                          OpenART 摄像头(拍摄+识别+决策)
                                    ↓
                            UART 115200 8N1
                                    ↓
                       MCU(NXP i.MX RT系列) → 电机 → 车移动
                                    ↓
                          里程计位姿反馈(50Hz $P帧)
```

**关键理解：摄像头拍屏幕，不是拍场地。** 屏幕同时显示俯视图（全局）和第一人称视角（各 720×540）。

| 项目 | 规格 |
|------|------|

| 项目 | 规格 |
|------|------|

- OpenART UART TX → MCU PA3 (USART2 RX)
- OpenART UART RX → MCU PA2 (USART2 TX)
- 波特率：115200, 8N1

## 四、通信协议

### 下行（视觉 → MCU）
| 指令 | 格式 | 用途 |
|------|------|------|
| 速度 | `$V,vx,vy,wz*XX\n` | 控制车移动，vx∈[-2,2]m/s, vy∈[-2,2]m/s, wz∈[-6,6]rad/s |
| 停车 | `$S*XX\n` | 紧急停车（不经减速，立即停） |
| 位姿校正 | `$R,x,y,yaw*XX\n` | AprilTag 定位后校正里程计 |

### 上行（MCU → 视觉）
| 指令 | 频率 | 用途 |
|------|------|------|
| `$P,x,y,yaw,vx,vy,wz\r\n` | 50Hz (每20ms) | 里程计位姿反馈，可用于闭环导航 |
| `$E,stall\r\n` | 事件触发 | 堵转/碰撞报警，收到后需重新规划 |

### 校验规则
`*` 后两位十六进制 = `$` 到 `*` 间所有字节 XOR。不带 `*` 也能解析（向后兼容）。

```python
def add_checksum(frame):  # frame = "$V,0.5,0,0"
    xor = 0
    for c in frame[1:]:
        xor ^= ord(c)
    return f"{frame}*{xor:02X}\n"
```

### 常用指令示例
```
$V,0.5,0,0*2C       # 纯右移 0.5m/s
$V,0,0.8,0*08       # 快速前进 0.8m/s
$V,0,0,-1.5*1A      # 顺时针旋转
$S*53                # 紧急停车
$R,1.5,2.0,1.57*0B  # 校正位姿
```

> MCU 内部有加速度限制（0.8 m/s², 2 rad/s²），速度不会突变，可放心发大值。

## 五、游戏任务详解

### 任务A：推箱子 (Sokoban) — 当前比赛拟定任务

**基本规则**：场地中生成多个可移动箱子与对应目的地，车模需将箱子推到目的地位置，成功后两者同时消失。

#### 三种难度关卡
| 难度 | 名称 | 规则 |
|------|------|------|
| 1 | 传统推箱子 | 通过颜色识别，将可移动箱子推到指定目的地 |
| 2 | 按图片分类推箱子 | 箱子侧面贴卡通图案，需根据图案类型推到对应数字(0-9)的目的地；目的地并排排列降低难度 |
| 3 | 分类推箱子升级版 | 目的地随机分散摆放，需先识别目的地数字，再寻找对应图案的箱子推动 |

#### 虚拟元素
| 元素 | 颜色/特征 | 尺寸 | 说明 |
|------|-----------|------|------|
| 可移动箱子 | 橙黄色 (135,210,255) | 30×30 px | 顶部颜色，四周可能贴图/数字 |
| 目的地 | 紫色 (170,0,255) | 30×30 px | 四周贴数字 0-9 |
| 车模(RGB) | 红色(255,0,0) / 蓝色(0,0,255) | — | 两个色块确定位置和朝向 |
| 围墙 | 黑灰色 (90,90,90) | 20px 宽 | 不可穿越 |
| 炸弹 | 特定图标 | — | 可炸毁内部围墙（外围围墙不可炸） |

#### 计分与判罚
- **结束条件**：全部箱子消失 / 剩余箱子无法推动 / 越过外围围墙
- **罚时**：每未完成一个箱子 +30 秒；需完成半数以上箱子才计有效成绩
- **触碰炸弹**：比赛结束
- **穿越外围围墙**：计时停止

#### 基本策略
绕到箱子背面 → 对准边界/目的地方向 → 直线推出

#### 比赛模式
- **闯关模式**：单人计时竞速
- **对抗模式**：双车同场，规定时间内推箱子多者胜

---

### 任务B：飞机大战 (Plane Wars) — 练习/备赛系统

车模物理移动映射为虚拟战机飞行轨迹，车模朝向映射为射击方向。

#### 单人智能挑战模式
| 项目 | 规则 |
|------|------|
| 通关条件 | 累计消灭 15 架敌机 |
| 敌机数量 | 最多同时 3 架，难度递增 |
| 初始生命 | 3 点 |
| 罚时 | 每损失 1 点生命 +10 秒 |
| 成绩核算 | 完成任务总耗时 + 罚时 |
| 失败判定 | 生命值耗尽且未击落足够数量飞机 |

#### 识别目标
| 目标 | 特征 | 用途 |
|------|------|------|
| 敌机 | 不同颜色/形状飞机图标 | 瞄准射击 |
| 敌方子弹 | 小圆点/线条，有运动方向 | 预判轨迹、闪避 |
| 我方飞机 | 特定颜色箭头 | 确认位置 |
| 道具 | 特殊图标 | 路径经过时拾取 |

#### 双人智能对抗模式
- 两车同场竞技，红蓝队伍区分
- 场景随机刷新道具，抢夺可增强自身或削弱对手
- 进阶机制（验证中）：手动发射、弹药有限、需补给
- 获胜条件（满足其一）：耗尽敌方生命值 / 规定时间结束时得分更高

#### 基本策略
躲子弹优先 → 对准敌机（调整车朝向）→ 保持射击线

## 七、识别算法方案

### 方案A：传统视觉（推荐起步）
- HSV 颜色阈值分割（比 RGB 耐光照变化）
- 轮廓检测（findContours）
- 模板匹配（matchTemplate，识别数字标签）
- **优点**：快、无需训练、OpenART 原生支持
- **缺点**：光照敏感，需手动调参

### 方案B：轻量 CNN（进阶可选）
- YOLOv5-nano / MobileNet-SSD
- INT8 量化部署到 OpenART
- **优点**：鲁棒性好，对光照/角度变化不敏感
- **缺点**：需标注训练数据、调优周期长、OpenART 算力受限

## 八、关键技术点

1. **坐标映射标定**：屏幕像素坐标 → 场地物理坐标(m) → 速度指令(m/s, rad/s)
2. **投屏延迟补偿**：WiFi 有 50-100ms 延迟，需预测当前真实位置
3. **HSV 色彩空间**：比 RGB 更耐光照变化，比赛现场光照可能与实验室不同
4. **安全机制**：MCU 500ms 超时停车 + 堵转检测 + 碰撞检测，代码崩溃车自动停
5. **帧率保障**：识别+决策+发送 < 50ms（≥20fps），否则车反应迟钝
6. **屏幕反光**：摄像头角度需避免屏幕反光，可加遮光罩
7. **标识牌颜色**：已从黄色改为灰绿色 RGB(90,179,89)，避免与场地黄边框冲突
