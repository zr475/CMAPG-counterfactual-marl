视觉组技术方案 第21届智能车 - AI视觉组

核心任务: 用 OpenART 摄像头识别车载手机屏幕上的游戏画面 (屏幕显示裁判系统投屏的虚拟游戏), 实时输出运动指令给 MCU, 控制车模在 3.2m x 2.4m 场地完成推箱子/飞机大战任务。

关键理解：摄像头拍屏幕，不是拍场地

  • OpenART 摄像头朝向 车载手机屏幕，拍摄屏幕上显示的游戏画面
  • 屏幕同时显示 两个视角：俯视图 (全局) + 第一人称视角 (各720×540)
  • 车模在场地上的位置由 裁判系统全局摄像头 + 车顶 AprilTag 标识牌定位
  • 摄像头不需要看场地，只拍屏幕

任务A: 推箱子 (Sokoban)

屏幕上会显示:

  • 你的车 (红色箭头) 的位置和朝向
  • 带数字标签的箱子 (需要推出边界)
  • 炸弹 (碰到就失败)
  • 场地边界

你需要识别:

目标特征用途
自己的车红色箭头确定当前位置和朝向
目标箱子带数字的方块确定推送目标
炸弹特定图标路径规划时避开
边界场地边缘线确定推出方向

任务B: 飞机大战 (Plane Wars)

屏幕上会显示:

  • 你的飞机 (车的物理位置映射)
  • 敌机 (1-3架, 会移动)
  • 敌方子弹 (需要躲避)
  • 道具 (可选拾取)

你需要识别:

目标特征用途
敌机不同颜色/形状的飞机图标瞄准射击 (车朝向=射击方向)
敌方子弹小圆点/线条, 有运动方向预判轨迹, 闪避
自己的飞机特定颜色箭头确认位置
道具特殊图标路径经过时拾取

策略: 躲子弹优先 -> 对准敌机 (调整车朝向) -> 保持射击线

成绩: 击落15架, 时间越短越好, 每掉1血罚时10秒

三、通信协议

你发给MCU的 (下行)

格式示例说明
$V,vx,vy,wz*XX\n$V,0.5,0,0.1*3A\n设置速度
$S*XX\n$S*53\n紧急停车
$R,x,y,yaw*XX\n$R,1.5,2.0,1.57*0B\n校正里程计位姿 (AprilTag定位后)

MCU发给你的 (上行)

格式频率说明
$P,x,y,yaw,vx,vy,wz\r\n50HzMCU里程计位姿, 可用于路径规划
$E,stall\r\n事件堵转/碰撞, 收到后需重新规划

校验说明 (*XX)

* 后面两位十六进制 = $ 到 * 之间所有字节的 XOR。不带 * 也能解析 (向后兼容)。

# Python 计算校验的方法:
def add_checksum(frame):
    # frame = "$V,0.5,0,0"
    xor = 0
    for c in frame[1:]:  # 跳过'$'
        xor ^= ord(c)
    return f"{frame}*{xor:02X}\n"

速度字段范围

字段范围含义
vx-2.0 ~ +2.0横向速度 (m/s), 正=右移
vy-2.0 ~ +2.0纵向速度 (m/s), 正=前进
wz-6.0 ~ +6.0旋转角速度 (rad/s), 正=逆时针

注: MCU 内部有加速度限制 (0.8 m/s², 2 rad/s²), 速度不会突变, 可以放心发大值。

常用指令示例

$V,0.5,0,0*2C       # 纯右移 0.5m/s
$V,0,0.8,0*08       # 快速前进 0.8m/s
$V,0,0,-1.5*1A      # 顺时针旋转
$S*53                # 紧急停车 (立即停, 不经减速)
$R,1.5,2.0,1.57*0B  # 校正位姿 (AprilTag定位后发)

硬件连接

OpenART UART TX → MCU PA3 (USART2 RX)

OpenART UART RX → MCU PA2 (USART2 TX)

波特率: 115200, 8N1

  • 优化识别帧率 (目标: 20fps+)
  • 调整决策参数

五、识别算法建议

方案A: 传统视觉 (推荐起步)

  • 颜色阈值分割 (HSV空间) -> 找红色箭头/蓝色箱子
  • 轮廓检测 -> 确定位置和大小
  • 模板匹配 -> 识别数字标签
  • 优点: 快, 不需要训练, OpenART能跑

方案B: 轻量CNN (进阶)

  • YOLOv5-nano 或 MobileNet-SSD
  • 训练数据: 截图游戏画面, 标注目标
  • 量化后部署到 OpenART (INT8)
  • 优点: 鲁棒性好, 但需要训练数据和调优

PC端测试脚本 (快速验证用)

# test_vision.py - 用PC模拟视觉模块发指令
import serial, time

def checksum(frame):
    xor = 0
    for c in frame[1:]:
        xor ^= ord(c)
    return f"{frame}*{xor:02X}\n".encode()

ser = serial.Serial('COM3', 115200)  # 改成你的串口号

# 测试前进
ser.write(checksum('$V,0,0.5,0'))
time.sleep(2)

# 测试右移
ser.write(checksum('$V,0.5,0,0'))
time.sleep(2)

# 测试旋转
ser.write(checksum('$V,0,0,1.0'))
time.sleep(1)

# 校正位姿 (假设AprilTag定位到 x=1.0, y=0.5, yaw=0)
ser.write(checksum('$R,1.0,0.5,0'))

# 读取MCU上行位姿帧
while ser.in_waiting:
    line = ser.readline().decode().strip()
    if line.startswith('$P,'):
        parts = line.split(',')
        x, y, yaw = float(parts[1]), float(parts[2]), float(parts[3])
        print(f"位姿: x={x:.3f} y={y:.3f} yaw={yaw:.3f}")
    elif line.startswith('$E,'):
        print("⚠ 堵转报警! 需要重新规划路径")

# 停车
ser.write(checksum('$S'))
ser.close()

七、关键注意事项

#事项说明
1帧率识别+决策+发送 需要在50ms内完成 (20fps), 否则车反应迟钝
2延迟WiFi投屏有50-100ms延迟, 决策时需要预判
3光照比赛现场光照可能和训练时不同, 用HSV而非RGB做阈值
4屏幕反光摄像头角度要避免屏幕反光, 可加遮光罩
5坐标映射屏幕像素坐标 → 场地物理坐标 → 运动指令, 需要标定
6安全MCU有500ms超时停车 + 堵转检测, 代码崩溃车会自动停
7位姿反馈MCU每20ms发一帧 $P,x,y,yaw,vx,vy,wz, 可用于闭环导航
8堵转处理收到 $E,stall 说明撞墙了, 需要后退或换方向
